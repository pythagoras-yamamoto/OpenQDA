# KJ法ワークスペース (jev + Gemini)

インタビュー・議事録から、樽本徹也『UXリサーチの道具箱』の「付箋紙で分析」7ステップを再現するローカルWebアプリ。

**判断はjev、生成はGemini**という役割分担で実装している。

## 使い方(2段階のワークフロー)

toitta のように、自動化は切片化・分類までとし、その内容を人が確認・編集してから分析に進む。

1. **読み込み** — インタビューや議事録のテキストを貼り付け/ファイル選択し、「切片を作成」
2. **切片タブ** — 左に元データ(重要な発言に下線マーカー)、右に切片カード。ここで人が手を入れる
   - カードをクリック → 元の発言にジャンプ(逆も同様)
   - ✎ で文言を編集、✕ で削除、♡ でお気に入り、「お気に入りのみ表示」で絞り込み
   - 下線が引かれていない発言をクリックすると、その発言を切片として追加できる
   - 「切片を一括コピー」でクリップボードへ
3. **「グループ化へ進む」** — 確定した切片をもとにグループ化・図解化・文章化・検証を実行
4. **図解タブ / ストーリータブ** — 結果を確認

## 7ステップと担当

| ステップ | 内容 | 担当 |
|---|---|---|
| ① データを作る | 発言(行)単位に分割し、タイムスタンプと話者を抽出 | コード |
| ② 下線を引く | 「全部重要」にせず、分析に値する箇所だけを選ぶ | **jev**(`Noul`で1発言ずつ重要度を判定) |
| ③ カード化 | そのまま書き写さず、おおよそ20文字以内に要約 | **Gemini** |
| ④ グループ化・見出し | 似た内容を集め、各グループに短い見出しを付ける | **jev**(`Choice`)+ **Gemini**(見出し生成) |
| ④' 再グループ化 | 見出しを対象に、より大きなテーマへまとめ直す | jev + Gemini |
| ⑤ 図解化 | グループ間・グループ内カード間の前後関係/因果関係を把握し、枠と矢印で図示 | **jev**(`Score`で関連度、`Choice`で関係タイプ) |
| ⑥ アウトライン → 再文章化 | 新たなストーリーのアウトラインを作り、客観的な文章に再構成 | **Gemini** |
| ⑦ 検証・考察 | 元データとストーリーラインを照合し、矛盾や過度な解釈を検出 | **jev**(`Score`+`Noul`) |

⑦で矛盾や飛躍が検出された場合は「図解化に戻って再検討してください」と表示される。

### 図解の読み方

- **付箋(黄色)** = カード、**実線の箱** = グループ、**点線の枠** = 上位グループ
- **矢印(茶)** = 因果・手段、**矢印(青)** = 前後、**破線** = 類似、**点線(赤)** = 対立
- 関連の強いグループが隣り合うよう並べ替えている(似たものを近くに、異なるものを遠くに)
- カードにマウスを乗せると元の発言が表示される

## 制約・注意

- ①の分割はヒューリスティックで、「1行1発言」に近い形式を想定している(`00:23:17 話者名: 本文` のような形式に対応)
- グループ化(jev)は逐次処理のため、発言数に比例してAPI呼び出し回数が増える(上限300発言)
- ⑤の関係判定は、グループ間が最大120ペア、グループ内は隣接カード最大120ペアで打ち切る
- 図解の矢印は関連度の強い上位10本のみ描画する

## セットアップ

```sh
npm install
cp .env.example .env
```

`.env` に以下を設定する:

- `TYPESAFE_API_KEY` — https://console.typesafe.ai/home で発行
- `GEMINI_API_KEY` — https://aistudio.google.com/apikey で発行(無料枠は1日のリクエスト数が少ないため課金推奨)

## 起動

```sh
npm start
```

http://localhost:3200 を開き、議事録の`.txt`/`.md`ファイルを選択(または直接貼り付け)して「KJ法を実行」を押す。
